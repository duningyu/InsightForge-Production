# InsightForge｜工作区开发启动说明

**用途：** 将本套 `docs/mainline/IF_GUIDE_R1/` 放入 InsightForge 当前工作区后，把下面的启动任务交给该工作区的开发助手。不要在另一个产品的工作区运行，也不要用早期压缩包替代当前仓库。

## 推荐阅读顺序
`MAINLINE_RULES.md` → `TECHNICAL_ROUTE.md` → `WORKSPACE_RULES_APPEND.md`。来源有疑问时读 `SOURCES.md`。阅读版 Word 是同一正文的排版版本，并附来源页；开发引用 Markdown。

## 可直接复制的启动任务

你正在 InsightForge 的已有工作区工作。本次要实现 `IF_GUIDE_R1` 的第一个最小切片，不是从零创建产品。

先读取当前 AGENTS.md、相关项目规则和以下文档：
- `docs/mainline/IF_GUIDE_R1/MAINLINE_RULES.md`
- `docs/mainline/IF_GUIDE_R1/TECHNICAL_ROUTE.md`
- `docs/mainline/IF_GUIDE_R1/WORKSPACE_RULES_APPEND.md`
- `docs/mainline/IF_GUIDE_R1/SOURCES.md`

**目标：** 让只有 idea、没有资料的新手，根据学习／自用／给别人使用的目的，获得一张可执行、可保存和恢复的首次行动卡。

**先做 M0，但不要停在盘点：**
检查当前分支和未提交修改；读取实际启动链、受影响服务、数据库／存储、前端入口及相关测试。不要打印秘密值。生成一页 `docs/mainline/IF_GUIDE_R1/WORKSPACE_MAP.md`，列出现有等价能力、实际文件位置、当前可运行的测试命令，以及这次真正需要新增的最小内容。此文件只记录已查到的事实；不要捏造路径或命令。

**然后实施 M1：**
复用项目、IdeaBrief、账号与存储。增加或映射项目目的、行动目标／输入／步骤／产物／检查／分支。先用受控模板，不默认新增模型请求。在现有首页接入目的与当前行动，完成编辑、保存、重新打开和账号切换。验证历史项目未指定目的时仍可正常使用。

沿用工作区现有计划、测试和评审方式。对每个行为先补能失败的测试，再实现并执行相关回归。新增逻辑要通过实际应用生命周期、认证、数据库和前端路径；替换外部 HTTP 传输可以，绕过实际业务服务不可以。

**边界：**
首次行动不要求正式 Snapshot、完整市场证据或 PRD。用户确认不能成为市场验证；模拟记录不能写成真实访谈。保留正式 Handoff 的全部既有合同，本轮不为了零资料起步删 validator、回填 approved 或改结算语义。

本轮不自动请求真实模型、下载付费内容、写云数据库、上线或执行用户上传代码。存在已获准且适用于本任务的外部验证时，严格按其环境、次数和预算执行并报告；没有授权则完成不依赖外联的离线链，真实外部能力标为未验收。

如果当前工作区存在禁止本地功能修改的冻结，先指出具体冲突与最小需要确认的范围；不得自行解除。仅生产发布冻结不应被当成所有本地研发的禁止，但必须服从工作区实际规则。

**停止条件：**
完成 M1 的最小端到端路径和对应回归后停止，不自动推进 M2—M4。真正缺少必要依赖时，只阻塞依赖该能力的部分，并完成其余获准部分。

**最终只报告事实：**
本轮改动文件与对应规则；实际执行的测试及结果；未运行和失败项；网络／模型／云访问及费用；迁移和缓存失效范围；浏览器中实际完成的动作；仍存限制；建议的一个最小下一任务。没有运行的内容明确写未运行，不继承旧报告 PASS。

## 后续轮次
M1 完成后，再把 TECHNICAL_ROUTE.md 中的下一里程碑拆成当前仓库可执行的小任务。每轮重新确认相关实现与运行证据，不重复开展全项目治理盘点。
