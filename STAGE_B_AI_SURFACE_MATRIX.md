## Layer boundary audit

- L1 Provider raw response currently exists inside `ModelAdapter._request`, `_response_diagnostic`, and private attempt/diagnostic paths. Stage B tests must prove it never enters public DTOs.
- L2 normalized model output currently passes through `_content_from_response` and direct `json.loads` in `ModelAdapter._generate` / `_generate_async`; this is the primary normalization boundary to harden.
- L3 validated domain objects are Pydantic models (`AIReferenceDraft`, `EvidenceGuidanceDraft`, `SolutionSetDraft`, `SolutionCandidateDraft`) and document/snapshot service objects.
- L4 is rendered by typed DOM construction in `renderAIReference`, `renderEvidenceGuidance`, `renderSolutions`, document renderers, and `renderHandoff`; Stage B must add surface-specific completeness assertions.

## Current risk inventory

1. Structured provider parsing has no single explicit normalization result and no fixture coverage for fences, wrappers, multiple objects, or malformed tails.
2. `AIReferenceService` and `EvidenceCoachService` validate Pydantic shape and non-empty content, but do not yet share a typed output-contract failure boundary.
3. `renderAIReference` uses `JSON.stringify` for an item key; it does not render that key, but a denylist test is required to prevent regression.
4. Async solution public payload is contract-safe by construction only for terminal response contents; Stage B needs explicit raw-field denylist checks.
5. Document generation is deterministic/local in the current baseline and must be tested for snapshot/selected-solution inheritance, not treated as evidence of live-provider quality.
