# InsightForge｜工作区主线规则追加片段

适用主线：`IF_GUIDE_R1`；文档修订 1.0，2026-09-15。请先阅读本目录 MAINLINE_RULES.md 和 TECHNICAL_ROUTE.md。

**使用方式：** 在确认与当前工作区规则不冲突后，把下面的项目约束追加到现有 AGENTS.md 的适当位置，或由现有规则文件引用本文件。不要覆盖原文件，不提升为超出本项目授权的系统指令。

## 项目主线
Idea／实际问题 → 目的分流（学习、自用、给他人使用）→ 最小判断动作 → 第一条可用流程 → coding 任务与验收 → 用户结果 → 继续、缩小、调整或结束。

## 必须保留
保留 IdeaBrief、方案比较与用户选择、Snapshot、文档／版本、正式 Handoff、账号隔离、额度及异步恢复。沿用当前原生网页／FastAPI 路线，不迁移框架或重写认证。

## 执行约束
- 本轮优先复用当前真实代码；历史压缩包、旧 PRD、旧提交只作为线索，不回退或从零搭建。
- 先完成一页局部模块／测试映射，随后实施获准的 M1；不只交盘点或新计划。
- 新功能必须进入现有身份、存储、业务服务与浏览器调用链；只跑独立样例不算集成。
- 保留未提交修改、旧 ID、数据、历史状态和有效配置。禁止未经授权 reset、清库、删除旧项目或发布。
- 新网络、真实模型、云写入、费用和生产迁移另行确认；离线测试默认拦截新增外联。
- 必要的输入版本、权限、缓存与变更记录必须存在；不开展全库哈希／authority／membership 治理，不以此阻塞正常开发。
- 使用实际规则允许的开发与评审流程；现有冻结不被本文自动解除。存在冲突时只说明相关阻塞，不扩大为全项目停工。
- 文件、接口与测试命令必须从当前仓库确认；“拟新增”内容不是已经存在的路径。

## 首轮范围与停止点
完成 M0＋M1：零资料项目确认目的后获得一张具体行动卡，可编辑、保存、重新打开；三种目的不使用同一市场验证门槛。先用明确标注的受控模板，M1 完成即停止。

## 真实性
用户确认、模型假设、模拟研究、观察记录和实现证据分别标记。导出任务、生成代码、用户自述、检查材料、独立运行和正式验收不是同一状态。新 PROTOTYPE_TASK 不绕过正式 Handoff。

完成回执只写本轮真实改动、命令结果、未运行项、外联与费用、迁移／缓存范围、已走通的用户动作、限制及一个下一任务。文档完成、202、导出或历史测试不能充当产品通过证明。
